# Abuse Checker

Сервис для автоматической проверки пользователей VPN по географии их IP-адресов. Он получает активные подключения из Remnawave, определяет города IP-адресов через базу MaxMind GeoLite2 City, уведомляет администраторов в Telegram и переводит обнаруженных пользователей в блокирующий squad.

> **Важно:** приложение не является одноразовой CLI-проверкой. После запуска оно работает в бесконечном цикле и выполняет проверки через интервал `SLEEP`.

## Возможности

- получение списка узлов и активных подключений из Remnawave API;
- исключение узлов с тегом `NO_REAL_IP`, где проверка реального IP не имеет смысла;
- объединение IP-адресов пользователя между всеми проверенными узлами;
- геолокация IP по локальной базе MaxMind GeoLite2 City;
- обнаружение пользователей, которые видны в большем количестве российских городов, чем допускает их лимит устройств;
- отправка HTML-сообщений в Telegram-топик;
- автоматическое обновление блокирующего squad в Remnawave;
- периодическое обновление локальной базы MaxMind (если ей больше 7 дней).

## Как работает проверка

Один проход выполняется функцией `scan()` в следующем порядке:

1. Создаётся общая `aiohttp.ClientSession`. Если задан `PROXY`, он используется для HTTP-запросов приложения.
2. Проверяется локальный файл `DATA_DIR/maxmind/database.mmdb`.
   - Если файла нет, GeoLite2 City скачивается из MaxMind.
   - Если файл старше 7 дней, он скачивается заново.
   - Если файл актуален, повторная загрузка не выполняется.
3. Через Remnawave запрашивается список узлов (`GET /api/nodes`). Узлы с тегом `NO_REAL_IP` пропускаются.
4. Для каждого оставшегося узла запускается запрос подключений (`POST /api/connections/by-node/{node_uuid}`). Remnawave возвращает фоновую задачу; сервис проверяет её статус не более 15 раз с паузой 3 секунды, затем читает список пользователей и их IP.
5. IP-адреса объединяются по `userId`. Повторяющийся IP на разных узлах считается один раз.
6. В дальнейшую обработку попадают пользователи минимум с четырьмя уникальными IP (`min_session_count=4`). Для них запрашиваются данные пользователя (`GET /api/users/{user_id}`). Пользователи без `hwidDeviceLimit` исключаются.
7. Если количество уникальных IP не превышает `hwidDeviceLimit × 3`, пользователь считается нормальным и удаляется из списка нарушителей. Таким образом, текущий множитель лимита устройств равен **3**.
8. Для оставшихся пользователей MaxMind определяется город каждого IP. Учитываются только IP, для которых страна имеет ISO-код `RU`; города дедуплицируются.
9. Нарушением считается количество уникальных российских городов, большее чем `hwidDeviceLimit × 3`.
10. Если нарушений больше пяти, сначала отправляется сводное сообщение. Затем обрабатываются только первые пять нарушений: администратору отправляется подробный отчёт, а пользователю через `PATCH /api/users` устанавливается `REMNAWAVE_BLOCK_SQUAD`.

Сообщение для администратора формируется в `src/analyzers/_geo.py` и хранится в поле `for_admin_message`.

После успешного прохода сервис ждёт `SLEEP` секунд, разбивая ожидание на десять частей и выводя прогресс в лог. При исключении ошибка записывается в лог, затем сервис ждёт 60 секунд и повторяет попытку.

## Права Remnawave API-ключа

Remnawave API-ключ должен иметь доступ к каждому используемому endpoint. Авторизация выполняется через заголовок `Authorization: Bearer <REMNAWAVE_API_TOKEN>`.

| Метод | Путь | Тип доступа | Назначение |
|---|---|---|---|
| `GET` | `/api/nodes` | Чтение | Получение списка узлов и их тегов. |
| `POST` | `/api/connections/by-node/{node_uuid}` | Запись по HTTP-методу (логически чтение) | Запуск получения активных подключений конкретного узла. Endpoint возвращает `jobId`; данные не изменяются, но для API-ключа требуется разрешение на `POST`/запись. |
| `GET` | `/api/connections/by-node/{job_id}` | Чтение | Проверка фоновой задачи и получение результата сессий после её завершения. |
| `GET` | `/api/users/{user_id}` | Чтение | Получение `hwidDeviceLimit`, `telegramId` и `username` пользователя. |
| `PATCH` | `/api/users` | Запись | Установка `activeInternalSquads` для обнаруженного нарушителя. В тело запроса передаются `id` и `activeInternalSquads`. |

### Минимальный набор разрешений

Для штатной работы сервиса API-ключу нужны:

- чтение: `GET /api/nodes`;
- чтение: `GET /api/connections/by-node/{job_id}`;
- чтение: `GET /api/users/{user_id}`;
- запись по HTTP-методу, логически чтение: `POST /api/connections/by-node/{node_uuid}`;
- запись: `PATCH /api/users`.

Если требуется только анализ без автоматической блокировки, права на `PATCH /api/users` всё равно сейчас формально необходимы для полного сценария: сервис отправляет уведомление, а затем пытается изменить squad пользователя. Чтобы запускать его в режиме только чтения, потребуется отдельное изменение кода.

## Структура проекта

```text
.
├── Dockerfile
├── docker-compose.yml
├── .env.example                # шаблон переменных окружения
├── requirements.txt

    ├── main.py                    # бесконечный цикл и orchestration одного прохода
    ├── settings.py                # настройки из окружения и .env
    ├── analyzers/
    │   ├── _geo.py                # географический анализ и формирование отчётов
    │   └── _result.py             # результат анализа и время отчёта
    ├── clients/
    │   ├── maxmind/_client.py     # загрузка и чтение GeoLite2 City
    │   └── remnawave/             # HTTP-клиент узлов, подключений и пользователей

```

## Требования

- Python 3.12 или совместимый Python 3;
- доступ к Remnawave API;
- учётная запись MaxMind с `account_id` и `license_key` для скачивания GeoLite2 City;
- Telegram-бот с правом писать в целевой чат/топик;
- Docker и Docker Compose — если используется контейнерный запуск.

## Настройка окружения

Приложение читает `.env` из корня проекта через `pydantic-settings`. Файл `.env` не должен добавляться в Git.

Для начала скопируйте шаблон и замените placeholder-значения на параметры вашей инфраструктуры:

```bash
cp .env.example .env
```

После копирования файл `.env` содержит все параметры, необходимые для запуска, и может быть дополнен значениями конкретной инфраструктуры.

Пример содержимого:

```dotenv
REMNAWAVE_API_BASE_URL=https://remnawave.example.invalid
REMNAWAVE_API_TOKEN=<remnawave-api-token>
REMNAWAVE_BLOCK_SQUAD=<blocking-squad-uuid-or-name>

MAXMIND_ACCOUNT_ID=<maxmind-account-id>
MAXMIND_LICENSE_KEY=<maxmind-license-key>

TELEGRAM_BOT_TOKEN=<telegram-bot-token>
TELEGRAM_CHAT_ID=-1000000000000
TELEGRAM_TOPIC_ID=1

# Необязательные параметры с текущими значениями по умолчанию:
# PROXY=http://proxy.example.invalid:8080
# SLEEP=1800
# DATA_DIR=data
```

### Переменные

| Переменная | Обязательна | Назначение |
| --- | ---: | --- |
| `REMNAWAVE_API_BASE_URL` | Да | Базовый URL Remnawave API. Завершающий `/` удаляется перед построением путей. |
| `REMNAWAVE_API_TOKEN` | Да | Bearer-токен для Remnawave API. |
| `REMNAWAVE_BLOCK_SQUAD` | Да | Значение `activeInternalSquads`, устанавливаемое нарушителю. |
| `MAXMIND_ACCOUNT_ID` | Да | Account ID MaxMind для Basic Auth при скачивании базы. |
| `MAXMIND_LICENSE_KEY` | Да | License key MaxMind. |
| `TELEGRAM_BOT_TOKEN` | Да | Токен Telegram-бота. Передаётся в URL Bot API. |
| `TELEGRAM_CHAT_ID` | Да | Числовой ID Telegram-чата. |
| `TELEGRAM_TOPIC_ID` | Да | Числовой ID топика (`message_thread_id`). |
| `PROXY` | Нет | HTTP-прокси для `aiohttp`; по умолчанию отсутствует. |
| `SLEEP` | Нет | Интервал между успешными проходами в секундах; по умолчанию `1800` (30 минут). |
| `DATA_DIR` | Нет | Каталог локальных данных; по умолчанию `data`. |

Поле `debug` присутствует в `settings.py`, но текущий код его не использует. Все обязательные переменные должны быть предоставлены через окружение или `.env` до запуска приложения.

## Запуск в Docker Compose

1. Установите Docker и Docker Compose.
2. Заполните `.env` в корне проекта.
3. Запустите сервис:

   ```bash
   docker compose up -d --build
   ```

4. Посмотрите логи:

   ```bash
   docker compose logs -f abuse-checker
   ```

5. Остановите сервис:

   ```bash
   docker compose down
   ```

Compose передаёт `.env` в контейнер и монтирует `./data` в `/app/data`. Благодаря этому база MaxMind сохраняется между пересозданиями контейнера. Политика `restart: unless-stopped` автоматически перезапускает контейнер после сбоя или перезагрузки Docker-хоста.

## Локальный запуск

Рекомендуется использовать виртуальное окружение:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
PYTHONPATH=src python src/main.py
```

При локальном запуске `.env` также должен находиться в корне проекта, а каталог `data/` будет создан автоматически при первом обращении к MaxMind.

## Логи и диагностика

Логи выводятся в stdout с уровнем `INFO` и форматом:

```text
[LEVEL] filename | function -> message
```

Полезные сообщения:

- `Maxmind database not found. Downloading...` — база ещё не скачана;
- `Maxmind is deprecated. Updating...` — база старше 7 дней;
- `Processing node: ...` — обрабатывается узел Remnawave;
- `User ... is normal` — пользователь не превысил предварительный лимит;
- `GEO ANALYZER` — началась географическая проверка;
- `Failed.` — проход завершился исключением и будет повторён через 60 секунд.

Если контейнер постоянно перезапускается сразу после старта, сначала проверьте наличие всех обязательных переменных и доступность Remnawave, MaxMind и Telegram из контейнера.

## Безопасность и обработка данных

Приложение обеспечивает следующие свойства:

- секреты не входят в исходный код и передаются интеграциям через переменные окружения;
- запросы к Remnawave и Telegram выполняются с авторизацией, заданной конфигурацией приложения;
- пользовательские данные обрабатываются в памяти в рамках текущего прохода и не записываются приложением в отдельную базу данных;
- для геопроверки используется локальная база MaxMind, а не передача каждого IP во внешний сервис геолокации;
- данные передаются только настроенным интеграциям: Remnawave используется для получения и блокировки пользователя, Telegram — для уведомления администратора;
- локальные runtime-данные и база MaxMind хранятся в каталоге `data/`, который исключён из Git.

Конфиденциальность также зависит от внешней инфраструктуры: настроенный URL Remnawave, Telegram-чат, прокси и параметры TLS определяются окружением запуска. При ошибках интеграций приложение может записывать в лог технический ответ API, поэтому содержимое логов относится к защищаемым данным. Сервис не предоставляет отдельного шифрования локального каталога, логов или Telegram-сообщений.

## Ограничения текущей реализации

- Проверяются только IP, которые MaxMind определяет как находящиеся в России (`RU`); зарубежные IP не увеличивают число городов.
- За один проход уведомляются и блокируются максимум пять пользователей. Остальные останутся кандидатами до следующего прохода.
- Запросы подключений к каждому узлу выполняются последовательно.
- Сервис изменяет `activeInternalSquads` нарушителя, поэтому перед запуском в production убедитесь, что `REMNAWAVE_BLOCK_SQUAD` указывает на правильный squad.
